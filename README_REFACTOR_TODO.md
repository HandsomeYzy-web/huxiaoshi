# 项目重构 Todo 清单

## 使用方式

这份清单用于把 `README_REFACTOR_PLAN.md` 里的方向拆成可执行任务。

建议你在实际推进时按下面方式使用：

- 每一项任务单独建 issue
- 每个 issue 明确负责人与预计时间
- 每周只推进 1 到 2 个高优先级主题
- 优先完成 `P0`，再做 `P1`，最后处理 `P2`

优先级定义：

- `P0`：必须优先完成，不做会持续放大成本
- `P1`：高价值任务，适合在结构稳定后推进
- `P2`：优化项，可以延后

## 一、工程治理

### T1. 前端增加 ESLint

- 优先级：`P0`
- 目标：建立前端最基本代码约束
- 任务：
- 安装并配置 `eslint`
- 接入 Vue + TypeScript 规则
- 增加 npm script：`lint`
- 对现有代码跑一次修复并处理关键报错
- 完成标准：
- 可以在前端目录执行 `npm run lint`

### T2. 前端增加 Prettier

- 优先级：`P0`
- 目标：统一格式，减少无意义 diff
- 任务：
- 安装并配置 `prettier`
- 增加格式化 script
- 配置忽略文件
- 完成标准：
- 可以执行统一格式化
- 主要源码文件格式一致

### T3. 建立前端类型检查流程

- 优先级：`P0`
- 目标：避免页面重构时出现隐式类型回归

- 清理临时 `any` 和弱类型模块声明
- 完成标准：
- 可以单独执行类型检查

### T4. 整理环境配置

- 优先级：`P0`
- 目标：降低环境切换和新成员接入成本
- 任务：

- 区分开发、测试、生产配置
- 明确前后端所需环境变量
- 完成标准：
- 新成员可根据说明完成本地启动

### T5. 整理项目文档

- 优先级：`P0`
- 目标：让启动、构建、调试流程标准化
- 任务：

- 写明依赖、数据库、存储、中间件要求
- 完成标准：
- 无需口头说明也能完成本地启动

### T6. 后端增加 pytest 基础框架
